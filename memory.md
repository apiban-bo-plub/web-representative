## Red Book Lagging Parallax Column — reverted (2026-08-24)
- Tried making the Red Book left column a **lagging parallax column** (media travels the full column height across the section's `contain` range via two nested `translate` animations on a named `view-timeline: --rbook block`). Geometry was exact — measured +185px of downward drift against 1358px of text scroll at a 778px viewport — but the user judged it "not working properly" and asked for the pre-parallax version back. **Reverted; the section is a `position: sticky` pin again, and `#story` is once more the page's only pinned section.**
- **Why it read as broken:** the drift is `100vh - M - 2P`, independent of section height. With `M = min(66vh, 620px)` the differential is only ~13.6% of the scroll distance, so it looks almost identical to a plain pin. An image that must stay visible across all three chapters cannot travel far — that ceiling is inherent to the pattern. If a stronger effect is wanted later, shrink the media (that is the only lever) or pick a different pattern (e.g. per-chapter image swap with its own travel).
- **Harness finding worth keeping: every scroll-driven animation on the page is inert in the automation tab.** With `visibilityState: hidden`, Chrome does not tick scroll timelines: `ViewTimeline.currentTime` is `null` for `.px-layer`, `.px-zoom` and any view-timeline animation, even with the subject squarely in view (only document-timeline animations report a currentTime). Workaround: apply keyframe end-states manually as inline `translate` at several t values and read `getBoundingClientRect()` — that validates box-model arithmetic and leaves only "does the timeline tick" for foreground sign-off.

## Cold Open — YouTube Embed Restored (2026-08-24)
- User asked for the YouTube video back in the first section. `src/components/HeroVideo.jsx` now renders the Shorts embed (`VIDEO_ID = 'JKFGev-fdqw'`) instead of a self-hosted `<video>`. The self-hosted version had been rendering as a bare still since `public/video/` was never populated.

- **An iframe has no `object-fit`, so cover is done in CSS by hand.** `.cold-open__frame` exposes its own size as `--co-w` / `--co-h` (it is a `calc()` of `--p`, so nothing else can read it), and `.cold-open__yt` sizes itself `max(--co-w, --co-h * 9/16)` × `max(--co-h, --co-w * 16/9)`, centres with `translate: -50% -50%`, and lets the frame's `overflow: hidden` clip the rest. This is strictly better than the pre-redesign version, which stretched a 9:16 source to fill the box. Verified at 354×630, 897×765 and 1440×900: aspect stays 0.562, both axes ≥ frame, centred.
- `scale: 1.22` on top of that is **not** decoration — it over-crops so YouTube's title card and progress bar (which still paint with `controls=0&modestbranding=1`) fall outside the frame. Do not remove it.
- Mobile `@container (max-width: 900px)` sets `--co-w/--co-h` **in `vh`, not `dvh`**, alongside the real `height: 100vh; height: 100dvh` pair.
